Support directional events: derive bucket, Void, and threshold position IDs, split and merge an event's complete bucket set, convert bucket NO positions, compose and decompose thresholds, and split and merge between two threshold lines. Directional conditions work with `splitPosition`, `mergePositions`, and `redeemPositions` without a market listing, and with condition filters. Add the `ATOMIC_DIRECTIONAL` and `INCREMENTAL_DIRECTIONAL` resolution types. Behavior for binary, neg-risk, combo, and CTF markets is unchanged.

Expose `mergeDirectional(positionIdA, positionIdB, amount?)` and `splitDirectional(positionIdA, positionIdB, amount?)`, accepting ABOVE on a lower line and BELOW on a higher line in either argument order. The SDK derives the event and line indices locally. Optional amounts are bigint values in six-decimal base units or `'max'`; omission defaults to fresh maximum balances, including collateral checks for splits. The corresponding `prepare*` methods use the same arguments. Add `decodePositionId`, read-only `findDirectionalPairs`, custom-signing workflows, and the four dedicated directional activity types with event-level and threshold-level models.

Add `findDirectionalBuckets(request?, options?)` to discover indexed middle-bucket YES holdings with fresh on-chain balances and optional protocol event filtering. Each `DirectionalBucketHolding` returns its position ID, event ID, bucket index, balance, required pUSD and the threshold position IDs for a singleton split. Balance and required pUSD use bigint six-decimal base units and are equal; discovery does not read wallet collateral or filter by affordability. Outer buckets, NO and Void are omitted. Results rank by descending balance with deterministic event/index ties; contiguous ranges can share collateral, so singleton requirements do not represent an optimal aggregate cost.

Add no-argument `mergeAllUserPositionsDirectional()` and `splitAllUserPositionsDirectional()` methods returning `DirectionalBulkResult` as `{ outcomes, errors }`, with confirmed transaction outcomes and detailed failure records. They discover indexed wallet holdings, refresh on-chain balances, execute sequentially and rediscover after each confirmation. Merge prioritizes the most collateral returned; split independently chooses feasible middle-bucket YES ranges using available collateral, prioritizing amount then range width. Both require existing approvals and retain previously confirmed effects. Definite failed pairs are recorded and skipped, with a 25-failed-pair limit. Transient discovery and confirmation reads receive up to three total attempts with backoff; confirmation retries reuse the same transaction handle without resubmission. Ambiguous submission, unresolved confirmation, persistent discovery failure and cancelled signing return a partial summary and pause further mutations. Greedy allocation is not globally optimal.
